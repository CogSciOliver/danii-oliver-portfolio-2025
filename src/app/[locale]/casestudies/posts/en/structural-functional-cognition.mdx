# Overview

This case study examines the debugging and refinement of a custom table-rendering system within a Next.js + MDX pipeline. The process is analyzed through the dual lens of structural-functional organization (cognitive science perspective) and user experience functional engineering (practical development perspective). The goal was to resolve a breakdown in expected behavior when Markdown tables failed to render properly, and to evolve a design that aligns cognitive clarity, functional structure, and user interaction affordances.

# Introduction

Software development is not only an engineering discipline but also a cognitive system. Developers form mental models of how components should behave, and when those models diverge from system outputs, cognitive dissonance arises. The structural-functional approach in cognitive science interprets this process as the interplay between internal representation (the developer's conceptual schema of "tables in Markdown") and functional adaptation (how the system actually processes and renders tables).

User experience functional engineering, by contrast, examines the external interface: how the system structures code, styling, and outputs to afford predictable, reliable interaction.

The incident analyzed here involves the misalignment between expected Markdown table rendering (`| col | col |`) and the custom React Table component designed for structured data.

# Problem

Observation: Tables written in .mdx files with Markdown pipe syntax were not displaying as expected.

Hypothesis (developer's mental model): Markdown tables should be intercepted by the custom Table component.

Reality (system's function): The MDX compiler generated `<table>`, `<thead>`, `<tr>`, `<td>` tags directly. Since mdx.tsx did not map these to styled components, they rendered unstyled and functionally disconnected.

# Intervention Steps

Cognitive Reframing (structural-functional adjustment):

Developer shifted mental model from "Markdown pipes map to `<Table />`" &rarr; "Markdown pipes map to raw HTML `<table>`."

Recognized that `<Table data={...} />` was a separate pathway requiring explicit use.

Functional Re-engineering (user experience adaptation):

Two possible strategies were identified:

Map Markdown-generated `<table>` tags to styled React components.

Use the custom `<Table data={...} />` component explicitly.

The decision was made to proceed with the custom component for precision and consistency.

## Styling Integration:

Introduced Table.module.scss to apply consistent borders, zebra striping, and dark mode adaptations.

Ensured functional connection by applying `className={styles.table}` to `<table>`.

Extended refinement by incorporating opacity-based background coloring for contextual adaptability.

# Assessment and Diagnosis

Cognitive Diagnosis: The breakdown stemmed from a schema mismatch between the developer's internal structural-functional model (expectation of interception) and the compiler's actual function (direct HTML output).

Engineering Diagnosis: The system lacked functional binding between Markdown output (`<table>`) and the intended Table component or its styles.

## Intervention and Management

Structural-functional intervention: Corrected the developer's conceptual model, enabling new mental pathways for how Markdown and MDX interoperate.

User experience functional intervention: Refactored the engineering system by:

Clarifying explicit component usage `<Table data={...} />`.

Binding visual structure through SCSS module integration.

Enhancing affordances via zebra striping and dark mode adaptation.

# Outcome and Follow-Up

Tables now render with consistent borders, spacing, and zebra striping.

Dark mode and opacity support provide environmental adaptability.

Developer's mental model is realigned with system function, reducing future cognitive friction.

This process created a repeatable structural-cognitive &rarr; functional-engineering loop, enhancing both user trust in the system and developer fluency.

## Discussion

This case demonstrates how software bugs are not only engineering defects but cognitive misalignments. Structural-functional analysis highlights that effective debugging requires reconfiguring the developer's conceptual schema. Once the mental model aligned with the system's real function, user experience functional engineering could refine the interface to support reliable, aesthetically coherent outputs.

# Key insights:

Structural-functional organization frames software interaction as cognitive adaptation between mental models and system behavior.

User experience functional engineering provides the external affordances, borders, striping, dark mode, that align visible outcomes with conceptual expectations.

The iterative loop between cognitive reframing and engineering refinement is central to sustainable software design.

## Conclusion

By reframing the developer's schema of Markdown table rendering and reinforcing functional bindings through styled components, the system now exhibits cognitive congruence and functional usability. This alignment underscores the value of integrating cognitive science perspectives with engineering practice, debugging is not merely code correction, but the restructuring of human-system interaction.
